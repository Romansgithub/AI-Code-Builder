# 妙笔生花 · AI 零代码应用生成平台

输入一句自然语言需求，AI 生成可运行的 Web 应用，并一键部署为可访问的站点。

后端 Java 21 + Spring Boot 3.4.1 + LangChain4j 1.1.0，前端 Vue 3 + Vite。

## 核心能力

- **三种生成策略**：原生 HTML 单页、多文件站点、Vue 工程，按需求复杂度选择
- **流式生成**：SSE 推送，生成过程实时可见，不必等整包返回
- **生成 → 构建 → 自愈**：构建失败按类型分类，仅编译类错误回喂同一会话记忆重建，最多 2 轮；依赖与环境类失败直接返回，不做无意义重试
- **多轮迭代**：在已有应用上继续对话修改，保留会话记忆
- **在线预览与下载**：生成结果可预览、可下载源码
- **一键部署**：构建产物部署为可访问站点

## 工程要点

### 多模型接入与降级

基于 LangChain4j 声明式 AI Service 接入 OpenAI 兼容的多模型，为生成、路由、自愈分别设计系统提示词。按故障类型（超时、限流、服务不可用）预设降级链路，主模型不可用时自动切换，避免生成中断。调用量与失败原因可通过评测接口观测。

### 生成 → 构建 → 自愈

构建失败不是一律重试，而是先分类：

| 失败类型 | 处理方式 |
| --- | --- |
| 编译类错误 | 回喂同一会话记忆，携带报错重建，最多 2 轮 |
| 依赖 / 环境类失败 | 直接返回，不做无意义重试 |

分类的意义在于：只有「改代码能解决」的错误才值得消耗模型调用，环境问题重试再多次也是失败。

### RAG 代码检索

按语义边界切块并用 text-embedding-v4 向量化，向量以二进制存 MySQL，查询时按余弦相似度与关键词得分加权融合，按文件哈希做增量索引。

自建代码检索标注集（v1.1，28 条用例：点名 8 + 语义 20），对三条链路做消融：

| 链路 | 整体 Recall | 语义型 Recall |
| --- | --- | --- |
| 仅关键词 | 75.0%（21/28） | 65.0%（13/20） |
| 仅向量 | 96.4%（27/28） | 95.0%（19/20） |
| 混合 0.7/0.3 | 96.4%（27/28） | 95.0%（19/20） |

引入向量召回后，语义型用例的 Recall 由 65% 提升至 95%。评测口径与逐条结果见 [docs/rag-eval.md](docs/rag-eval.md)。

### 生成质量评测

覆盖三种生成策略的 8 条固定回归用例 + 1 条故障注入用例，结果：

- 一次通过率 62.5%（5/8）
- 自愈后最终通过率 100.0%（8/8）

一次通过率是生成质量的基线，最终通过率是用户实际拿到可用项目的比例。两者之间的差距，就是自愈链路的实际价值。评测口径见 [docs/eval.md](docs/eval.md)。

## 快速开始

### 环境要求

- JDK 21
- Node.js 18+
- MySQL 8（或使用 H2 开发环境）

### 必要环境变量

```bash
export LLM_BASE_URL=https://your-openai-compatible-endpoint/v1
export LLM_API_KEY=your-key
export DB_URL=jdbc:mysql://localhost:3306/miaobi
```

其余可调项（模型降级、RAG 切块粒度、调用预算、自愈轮次）见 `src/main/resources/application.yml` 中的 `app.*` 配置段，均支持环境变量覆盖。

### 启动

```bash
# 后端，默认 8080
mvn spring-boot:run

# 前端
cd frontend
npm install
npm run dev
```

接口文档：启动后访问 `/swagger-ui/index.html`。
